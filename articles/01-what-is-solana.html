What is Solana?

An introduction for readers who have never worked with a blockchain.

  • levelbeginner
  • prerequisitesnone
  • reading time~9 min

01What is a blockchain?

A blockchain is a database that is not stored on a single server. Thousands of computers keep an identical copy and keep it synchronized.

Take a spreadsheet that records money transfers:

#FromToAmount
1AnaLuis10
2LuisMarta4
3MartaAna1

At a bank, this table lives on the bank's servers and only the bank can change it. On a blockchain:

  • Every computer in the network (called a node) has a copy of the table.
  • To add a new row, the network has to accept it under rules that every node knows.
  • Once a row is accepted, it cannot be edited or deleted.

Why is it called a chain of blocks?

Transactions are grouped into blocks. Each block stores the hash of the previous block. A hash is a fixed-length code calculated from some data: if the data changes by even one character, the hash changes completely.

This is how the network detects the change: block 2 still says a1, but block 1 now produces 3e. The other nodes still hold the original copy, so they reject the edited version.

02What is Solana?

Solana is a public blockchain. Besides recording money transfers, it can run programs (code) directly on the network.

PropertyValue
Native currencySOL
Smallest unitlamport (1 SOL = 1,000,000,000 lamports)
Slot time200 ms: one chance to produce a block every 200 ms (400 ms until October 2026)
Finality target~150 ms after a block is produced
Base fee5,000 lamports per signature (0.000005 SOL)
Main language for programsRust

The fee is what you pay the network to process your transaction. On Solana it is usually a fraction of a US cent. Finality is the moment a transaction can no longer be reversed.

03Key concepts

3.1 Accounts

On Solana everything is stored in accounts: balances, programs and application data. An account looks like a file with these fields:

json · example account
{
  "address": "7xKXtg2CW87d97TXJSDpbD5jBkheTqA83TZRuJosgAsU",
  "lamports": 1500000000,
  "owner": "11111111111111111111111111111111",
  "executable": false,
  "data": []
}
  • address: unique identifier of the account.
  • lamports: balance. Here 1,500,000,000 lamports = 1.5 SOL.
  • owner: the program allowed to modify the account. 1111…1111 is the System Program, the built-in program that handles SOL transfers.
  • executable: true if the account contains a program.
  • data: extra data. A simple wallet account has none.

3.2 Keys and addresses

To use Solana you need a keypair:

  • Public key: your address. You can share it, like a bank account number.
  • Private key: used to sign transactions and prove you are the owner.
[!] warning

Anyone who has your private key controls your funds. Never share it. Support teams, apps and websites will never ask for it.

A wallet (for example Phantom or Solflare) is the app that stores your private key and signs for you.

3.3 Transactions and instructions

A transaction is a signed request for the network to do something. It contains one or more instructions. Each instruction says:

  1. Which program to run.
  2. Which accounts it will read or modify.
  3. What data it receives.

A transfer of 0.1 SOL from Ana to Luis:

Transaction
├── Signature: Ana
└── Instruction
    ├── Program:  System Program
    ├── Accounts: [Ana (sender, writable), Luis (receiver, writable)]
    └── Data:     transfer 100,000,000 lamports

3.4 Programs

A program is code deployed on Solana. Other blockchains call it a smart contract. Programs can, for example, create a token, swap tokens or record who owns an NFT.

An important detail: Solana programs do not store their own state. Data lives in separate accounts that the program reads and modifies. Because every transaction lists the accounts it will use in advance, the network can run transactions that touch different accounts at the same time (section 04).

3.5 Validators

Validators are the computers that process transactions, produce blocks and vote on blocks produced by others. Their voting weight is proportional to their stake: the SOL locked with them, either their own or delegated by other holders. Validators earn rewards for this work.

04How Solana confirms transactions quickly

Three mechanisms work together.

4.1 Leader schedule

Time is divided into slots of 200 ms. For every slot, one validator is the leader: the only one allowed to produce a block for that slot. The schedule is known in advance and each leader gets 4 consecutive slots, so transactions are sent directly to the upcoming leader.

4.2 Parallel execution

Each transaction declares the accounts it will modify. Transactions that do not share writable accounts can run at the same time on different CPU cores:

TxTransferWritable accountsRuns
AAna → LuisAna, Luisin parallel with B
BMarta → PedroMarta, Pedroin parallel with A
CLuis → MartaLuis, Martaafter A and B (shares accounts with both)

4.3 Voting with Alpenglow

Since 21 October 2026, Solana uses the Alpenglow consensus protocol. Its voting component, Votor, works like this:

  1. Validators send their votes on a block directly to each other. Votes are no longer transactions stored inside blocks.
  2. Votes are combined into a certificate: compact proof that a given share of the stake voted for the block.
  3. If validators holding at least 80% of the stake vote for the block in the first round, the block is final.
  4. If not, a second round with a 60% threshold can finalize it.

The target is about 150 ms from block to finality. The previous protocol, TowerBFT, needed about 12.8 seconds.

[!] older tutorials are out of date

Guides written before October 2026 often describe Proof of History (PoH) as the core of Solana's speed. PoH is a chain of SHA-256 hashes used as a clock to record the order of events. With Alpenglow, PoH no longer paces block production. Those guides also give a 400 ms slot time, which is now 200 ms.

05Hands-on: your first transfer on devnet

Solana runs several networks:

NetworkUseDoes SOL have real value?
MainnetProductionYes
DevnetTesting and developmentNo

We will use devnet, so you will not spend real money. First install the Solana CLI by following the official guide: solana.com/docs/intro/installation.

1. Create a keypair

bash
solana-keygen new --outfile ~/my-wallet.json

2. Point the CLI to devnet and to your wallet

bash
solana config set --url devnet --keypair ~/my-wallet.json

3. Show your address (public key)

bash
solana address

4. Request test SOL

bash
solana airdrop 1
[i] if the airdrop fails

The devnet faucet limits how many requests you can make. Use the web faucet instead: faucet.solana.com.

5. Check your balance

bash
solana balance
# 1 SOL

6. Send 0.1 SOL to another address

bash
solana transfer <RECIPIENT_ADDRESS> 0.1 --allow-unfunded-recipient

The --allow-unfunded-recipient option lets you send SOL to an address that does not exist on the network yet.

The command returns a transaction signature. Search for it in the Solana Explorer (devnet) to see the transaction, the accounts involved and the fee paid.
