Create your own token on devnet

In this hands-on guide you create a token from the command line, mint 1,000 units, send some to a second wallet, freeze an account and lock the supply for good. Everything happens on devnet, so nothing you create has real value.

  • levelbeginner
  • prerequisitesSolana CLI installed, a wallet on devnet
  • time~15 min
  • toolssolana, spl-token 5.6
  • tested withspl-token 5.6.1 on a local validator

01Before you start

You need the Solana CLI, which already includes the spl-token tool used in this guide. Check that both are available:

bash
solana --version
spl-token --version

If spl-token is missing, you can install it with Rust's package manager:

bash
cargo install spl-token-cli --version 5.6.1

Then make sure the CLI points to devnet and that your wallet has some SOL to pay fees and deposits:

bash
solana config set --url devnet
solana balance
# if the balance is 0, request test SOL
solana airdrop 1
[i] if the airdrop fails

The devnet faucet limits how many requests you can make. Use the web faucet at faucet.solana.com instead.

The commands in this guide save addresses in shell variables such as $MINT, so you can copy them without editing. They work in bash and zsh; on Windows, use WSL.

Most steps include a screen with the output we got when running them, so you can compare it with yours. Your addresses and signatures will be different, and long values appear shortened with an ellipsis.

02Create the token

Creating a token means creating its mint account. The following command creates one with 6 decimals, like USDC, and with a freeze authority, which you will use later:

bash
spl-token create-token --decimals 6 --enable-freeze

The output includes a line that starts with Address: followed by the address of your new mint:

Copy that address into a variable, replacing the placeholder:

bash
export MINT=<YOUR_MINT_ADDRESS>

Now look at what you created:

bash
spl-token display $MINT

The supply is 0, the token uses 6 decimals, and your wallet appears as both the mint authority and the freeze authority. The token exists, but nobody holds any of it yet.

[i] about the flags

Without --decimals, the CLI uses 9. Without --enable-freeze, the mint has no freeze authority, and a freeze authority cannot be added once the mint exists.

03Create your account and mint 1,000 units

Before you can hold your token, your wallet needs a token account for it. This command creates your associated token account and pays its refundable deposit:

bash
spl-token create-account $MINT

The output starts with Creating account followed by the address of your token account:

Save it as well, because you will freeze this account in section 05:

bash
export MY_ACCOUNT=<YOUR_TOKEN_ACCOUNT_ADDRESS>

As the mint authority, you can now create units. Mint 1,000 and check the result:

bash
spl-token mint $MINT 1000
spl-token balance $MINT
spl-token supply $MINT

Both commands answer 1000. Behind the scenes, with 6 decimals, the token account stores the number 1,000,000,000, and you will see that raw number in section 06.

04Send tokens to a second wallet

To see a transfer, you need someone to receive it. Create a second wallet that will act as your friend and save its address:

bash
solana-keygen new --no-bip39-passphrase --outfile ~/friend.json
export FRIEND=$(solana address -k ~/friend.json)

Now send 10 units to that wallet:

bash
spl-token transfer $MINT 10 $FRIEND --fund-recipient --allow-unfunded-recipient

The two flags deal with the fact that your friend is brand new. Your friend has no token account for your token yet, so --fund-recipient tells the CLI to create it and pay its deposit from your wallet: that is the address shown on the Recipient associated token account and Funding recipient lines. --allow-unfunded-recipient confirms that you really want to send to a wallet that holds no SOL, which the CLI otherwise treats as a possible typo.

Check both balances:

bash
spl-token balance $MINT
spl-token balance $MINT --owner $FRIEND

You should see 990 and 10. The supply is still 1000, because a transfer moves units between accounts without creating or destroying any.

05Freeze and thaw an account

Because you created the mint with a freeze authority, you can block any token account of your token, including your own. Freeze yours:

bash
spl-token freeze $MY_ACCOUNT

Then try to send 5 more units to your friend:

bash
spl-token transfer $MINT 5 $FRIEND --allow-unfunded-recipient

The flag is still needed because your friend's wallet holds no SOL. This time the transfer fails with a long error:

Of all that text, two parts matter: the code 0x11, which is how the Token Program reports a frozen account, and the log line Account is frozen. The tokens are still there, but they cannot move until the freeze authority releases them. Thaw the account and try again:

bash
spl-token thaw $MY_ACCOUNT
spl-token transfer $MINT 5 $FRIEND --allow-unfunded-recipient

This time it goes through, and the balances are 985 and 15. This is the same mechanism an issuer such as Circle uses when it freezes USDC at a specific address.

06Lock the supply

Right now you could mint as many new units as you like. Many projects remove the mint authority to prove that the supply can never grow, and you can do the same:

bash
spl-token authorize $MINT mint --disable
[!] this cannot be undone

Once the mint authority is removed, nobody can restore it. On devnet that does not matter, but on mainnet, check twice before running this command.

Try to mint one more unit, and the command fails because no address is allowed to do it anymore:

bash
spl-token mint $MINT 1

The log line says it plainly: the total supply of this token is fixed. Look at the mint once more:

bash
spl-token display $MINT

The mint authority now reads (not set). Notice also that display shows the supply as 1000000000 rather than 1000: it prints the number stored in the mint, which is the amount multiplied by ten to the power of the decimals.

07See it in the explorer

Everything you did is public. Print the explorer link for your token and open it in a browser:

bash
echo "https://explorer.solana.com/address/$MINT?cluster=devnet"

The page shows the supply, the decimals, the two authorities, the token accounts that hold it and every transaction you sent, including the transfer that failed while your account was frozen.

08Summary

With a handful of commands you created a mint, opened token accounts for two wallets, moved units between them, used the freeze authority and fixed the supply by removing the mint authority.

CommandWhat it does
create-tokenCreates a mint account.
displayShows the details of a mint or token account.
create-accountCreates your token account for a mint.
mintCreates new units (mint authority only).
balance / supplyShows a balance or the total supply.
transferMoves units to another wallet.
freeze / thawBlocks or releases a token account (freeze authority only).
authorize … --disableRemoves an authority permanently.
